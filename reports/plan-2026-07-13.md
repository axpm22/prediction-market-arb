# Execution plan — speed + bettable-surface expansion (2026-07-13)

Two goals, one plan. Everything below was **measured on the live DB/logs on
2026-07-13**, not guessed. Every phase follows the binding workflow (SPEC §16):
reproduce (evidence quoted below) → failing test → minimal implementation →
full `pytest -q` → `arb report --daily` unchanged unless stated → commit.
Tests run on recorded fixtures only (rule 2). No invented endpoints (rule 3);
every new threshold is a config key (rule 4).

Context: the 07-11→07-12 stat collapse was the laptop sleeping on battery
(pmset log: Clamshell/Maintenance Sleep), **not** the model. Ops prerequisite,
zero code: run the supervisor under `caffeinate -s` on AC power.

## Part S — Speed (live lane first: it runs at ~39s against a 20s target)

### S1. Covering index for the live shortlist — the single biggest win
**Evidence:** `shortlist()` (arb/lanes/live.py:28) runs at the top of every
20s live cycle. Measured twice on the 6.5 GB / 9.6M-row quotes table:
11.7s cold, **10.2s warm** (10% CPU — I/O-bound row lookups).
`EXPLAIN QUERY PLAN` → `SCAN quotes USING INDEX idx_quotes_event_fetched`
(full 9.6M-entry scan; sport/start_utc/venue_market_id force a table lookup
per entry).
**Build:**
1. New migration in `arb/migrations.py`:
   `CREATE INDEX idx_quotes_shortlist ON quotes(fetched_at, event_key, sport, start_utc, venue_market_id)`.
2. Failing test first: fixture DB, assert the shortlist query's
   `EXPLAIN QUERY PLAN` output contains `COVERING INDEX idx_quotes_shortlist`.
3. No query text change, no semantic change. (Tested alternative — sourcing
   from the latest watch poll only — is 10ms but drops in-play events that
   left the pregame board; rejected.)
**Acceptance:** timed query on the live DB < 2s; live `cycle_secs` in the
poll annotation drops by ~10s. ~1h.

### S2. Parallelize live requotes (currently sequential, sum-of-venues)
**Evidence:** `run_live_cycle` loops `for venue, vi in by_venue.items()`
(arb/lanes/live.py:163) — kalshi → polymarket → sx one after another.
watch.py's own docstring: sequential fetching "self-inflicts inter-leg skew
… and is forbidden." Watch venue latencies today: sx 15.5s avg, pm 7.1s.
**Build:** mirror `watch.py::fetch_all_venues` — `ThreadPoolExecutor(
max_workers=len(by_venue))`, one status dict per venue, same
exception-to-status handling. Requoters already use thread-local Sessions
(base.py), so this is safe as-is.
**Test:** monkeypatched requoters that each sleep 0.2s; assert wall time
< 0.4s (overlap) and one failing venue still yields the others' quotes.
**Acceptance:** live cycle = max(venue) not sum; skew-outer rejects should
also fall (bonus, watch the daily report). ~1–2h.

### S3. Kalshi requoter: parallel per-series fetches
**Evidence:** `_requote_kalshi` (live.py:82) loops series tickers with one
GET each, sequentially.
**Build:** same executor pattern over the series list. ~30 min, ride along
with S2.

### S4. SQLite write/checkpoint hygiene
**Evidence:** store.py:31 sets WAL but leaves `synchronous` at FULL (fsync
per commit; sustained ~30 commits/s across children). WAL file is 244 MB —
checkpoint starvation from constant readers.
**Build:**
1. `PRAGMA synchronous=NORMAL` in `Store.__init__` (the standard WAL
   pairing; durability tradeoff is acceptable — worst case loses the last
   commit on OS crash, never corrupts).
2. `PRAGMA wal_checkpoint(TRUNCATE)` as a supervisor-owned daily slot next
   to backup (heartbeat.py `_schedule`), time under a `db.checkpoint_time`
   config key (rule 4).
**Test:** Store fixture asserts `PRAGMA synchronous` returns 1 (NORMAL).
**Acceptance:** WAL file < 50 MB after the slot fires. ~1h.

### S5. Archive before the hot DB triples (config only)
**Evidence:** quotes grow ~2.4M rows/day; `archive_after_days: 7` and the
project is 5 days old — `data/archive/` doesn't exist yet. Hot DB reaches
~21 GB before the first trim; every query above scales with it.
**Build:** `archive_after_days: 7 → 3` in config.yaml. Rule 7 intact —
archive DBs keep every quote. Watch the first scheduled run's log line
(counts verified before delete, per arb/archive.py).
**Acceptance:** `data/archive/2026-07.sqlite` exists; hot DB shrinks after
VACUUM. ~10 min + one supervised run.

### S6. Stop fetching the MLB schedule every cycle
**Evidence:** `run_cycle` → `fetch_mlb_schedule(cfg)` (arb/cycle.py:108) —
a sequential statsapi.mlb.com GET on the critical path of **every** watch
poll for data that changes a few times a day.
**Build:** module-level `(date, fetched_at, games)` cache in cycle.py with
TTL under config `mlb_schedule_ttl_mins` (suggest 15). On fetch failure
serve the stale copy (schedule is "an upgrade, not a dependency").
**Test:** two `run_cycle` calls within TTL → one underlying fetch
(monkeypatch counter). ~45 min.

### S7. Parallelize intra-venue pagination (coverage AND speed)
**Evidence:** sx 15.5s avg / pm 7.1s avg per watch poll, both hitting 30s
deadline truncations (`venue fetch truncated: sx` in scan.log) and the
soccer tag hits its 1000-event pagination cap every cycle.
**Build:**
1. polymarket.py:56 `fetch_books`: the POST /books chunks are independent —
   fan out with an executor (thread-local sessions already handle safety);
   keep the `Deadline` checks (monotonic reads, thread-safe).
2. sx.py:93 `_fetch_sport`: leagues are independent — executor over leagues
   inside each sport. Pagination *within* a league stays sequential
   (nextKey dependency).
**Test:** fixture-driven; assert quote sets identical to the sequential
path. **Acceptance:** watch `latency_ms` for sx/pm roughly halves; fewer
`PartialFetch` truncations → higher shortlist coverage than today's 60–67%.
~2–3h.

### S8. Log I/O hygiene
**Evidence:** unmatched.log wrote 260 MB on 07-11 — matching.py:132 logs
every unmatched pair on every poll, duplicates included.
supervisor-stdout.log is 679 MB (rich table dumps per cycle, repeated
backup warnings), never rotates.
**Build:** per-process `set()` of already-logged `(venue, sport, away, home)`
in matching.py — log each once per process lifetime; total count per poll
stays visible via a single summary line. Rotate supervisor stdout (pipe
through the existing logutil rotation or truncate at the backup slot).
~45 min. (S8 becomes much smaller once C1/C2 fix the two floods below.)

### C1. Fix the Polymarket soccer adapter — the largest single expansion
**Evidence:** every PM soccer quote is unmatched; unmatched.log shows
`'Yes' vs 'No'` — for 2-outcome WINNER markets `quotes_from_event`
(polymarket.py:86) takes `outcomes[0]/[1]` as away/home, but PM soccer
moneylines are per-team Yes/No markets ("Will X win?"), and soccer WINNER
is 3-way (draw) anyway. 14k quotes/window fetched, persisted, and thrown
away — while burning the soccer pagination budget.
**Build (investigate → fixture → implement):**
1. Record a gamma soccer event fixture (one live call, keyless — allowed).
   Confirm market shape: per-team Yes/No + a draw market, and which field
   carries the team (market `question`/`groupItemTitle` — verify from the
   fixture, rule 3: only fields that exist).
2. Failing test from the fixture: expect team-labeled WINNER quotes
   (normalized via aliases) + DRAW leg, YES side only.
3. Implement in `quotes_from_event`: when sport is 3-way and the market is
   per-team Yes/No, emit the YES token as a quote labeled with the team
   (and DRAW for the draw market). Matching already supports DRAW labels
   (§7.1, matching.py).
4. **PREREGISTRATION amendment first** (dated, before the first persisted
   poll with the fix): PM-soccer quotes become matchable → the candidate
   set changes.
**Payoff:** soccer is the biggest tag on PM and SX lists it too (SPORT_IDS
soccer=5) — this unlocks an entire sport cross-venue. ~3–4h.

### C2. WNBA — an in-season league currently 100% dropped
**Evidence:** July = WNBA mid-season. Kalshi "basketball_nba" quotes parse
to `'' vs ''` (360/360 unmatched); SX sends 'Dallas Wings W' vs
'Chicago Sky W' (124/285 unmatched). The NBA proper is off-season — this
whole bucket IS the WNBA.
**Build:**
1. Reproduce from a recorded kalshi fixture: which series tickers these
   are and why team extraction is empty (likely a WNBA series whose ticker
   format differs from the configured SPORT_SERIES parsing).
2. Decide the key: add `basketball_wnba` as a first-class sport (cleaner —
   activity gating, max_game_hours, consensus all key on sport) rather
   than overloading nba. Config: sports list, `live_lane.max_game_hours`,
   aliases for the 13 teams incl. the SX ' W' suffix
   (normalize_team already falls back only onto known canonicals — add
   them to aliases.json).
3. **PREREGISTRATION amendment** (new sport in the measured set) before
   first persisted poll.
**Payoff:** a whole live league on 3 venues during MLB-only season. ~3h.

### C3. Alias-gap curation loop (tennis 35%, MLB 18%)
**Evidence:** table above; these are name-normalization misses, not
structural.
**Build:** small `arb unmatched-report` command: aggregate distinct

(manual-first, same spirit as rule 11); re-run daily until the tail is
noise. No adapter changes. ~1h build, then minutes/day of curation.

### C4. Spread markets — a third market type on all three venues
**Evidence:** sx.py:23 `# 342 spread: ignore`; PM `sportsMarketType`
"spreads" filtered by IN_SCOPE_TYPES; kalshi spread series unconfigured.
Winner+total only ≈ half the two-sided sports surface.
**Build (gated, do after C1/C2 prove out):**

   half-point vs whole lines) into `data/verified_facts.md` — rule 6's

   TOTAL, reuse it. §7 math is line-agnostic for 2-outcome books.
3. Cross-venue SPREAD stays REVIEW until whitelisted per §18.2 (rule 6).
4. **PREREGISTRATION amendment** before first persisted poll.
~1 day. Roughly doubles matchable markets per game.
